# 浏览器下载加速（Edge 接管）

浏览器下载慢，多数时候不是宽带不够，而是**服务端按单连接限速**，而浏览器基本只开 1 个连接。这个工具把文件切成 N 段、并发拉取（HTTP Range），单连接 700KB/s 的源也能跑到 10MB/s 以上。

自带一个 Edge 扩展：你在浏览器里点下载，它自动把链接（连同 Cookie / Referer / UA）转给本地引擎，然后把浏览器自己那条取消掉。所以带登录态、带防盗链的站点也能接管。

## 实测

测试源：镜像站上同一个 38MB 文件（`ubuntu/ls-lR.gz`），16 连接。

| 方式 / 源 | 速度 |
|---|---|
| curl 单连接 @ 阿里云 | 678 KB/s |
| 本工具 16 连接 @ 阿里云 | 5.8 – 7.3 MB/s |
| aria2 1.37 @ 华为云 | 10.7 MB/s |
| **本工具 @ 华为云** | **11.7 MB/s** |

下载结果做过 gzip 全量解压 + CRC 校验（427,594,509 字节，无错），分块拼接没有问题。

关于 aria2：同源对比下它没有优势，还需要伪造浏览器 UA 才能过镜像站（否则直接 403），所以没有并进来——省掉一个 5.4MB 的二进制和一堆 UA / 证书坑。

## 安装（不用装 Python、不用装任何东西）

1. **双击 `start-server.cmd`**，窗口标题是"本地下载加速服务"。保持它开着（最小化即可）。
2. Edge 地址栏输入 `edge://extensions` → 打开左下角 **开发人员模式** → 点 **加载解压缩的扩展** → 选择**本文件夹**（这个 `download-accelerator` 目录本身）。
3. 点扩展的 **详细信息 → 扩展选项**，点 **测试连接**，显示"连接正常"就成了。

之后正常用浏览器下载：≥5MB 的文件自动转给本地引擎，浏览器那条会自己消失。扩展图标点一下是总开关，徽标 `ON` / `OFF`。

## 命令行用法

```
dl.exe https://example.com/big.iso
dl.exe https://example.com/big.iso -o 片子.iso --dir D:\Downloads --conns 8
```

`dl.exe` 是免安装单文件版。`dl.py` 是同源代码，装了 Python 的机器上可以直接跑，方便改。

## 参数怎么调

| 参数 | 默认 | 说明 |
|---|---|---|
| 并发连接数 | 16 | 稳妥值。遇到 **403 / 429 / 连接被重置**，降到 8 或 4 |
| 最小体积 | 5 MB | 小于这个不接管，小文件交给浏览器更省事 |
| 携带 Cookie | 开 | 需要登录才给下的站点必须开 |
| 携带 Referer | 开 | 防盗链站点必须开 |
| 未知大小也接管 | 开 | 服务端不给 Content-Length 时仍然接管 |
| 不接管域名 | 空 | 每行一个域名，命中的站点保持浏览器原生下载 |

## 断点续传

多连接下载时会在同目录生成 `<文件名>.dlparts.json`，记录每块已完成多少。中断后**重新提交同一个 URL**，会从断点接着拉。注意：续传依赖 URL 仍然有效，很多站点带时效 Token，过期只能重下。

## 它做不到的

- **服务端按 IP / 按账号限速**（不是按连接）时，多连接完全无效——网盘基本都是这么做的。
- 不支持 `blob:` / `data:` 链接、POST 提交的下载、需要点验证码才出链接的下载（这些仍交给浏览器）。
- 服务端忽略 `Range` 返回 `200` 时，自动退化单连接，不会拼错文件。
- 同名文件会覆盖，不会自动改名。

## 排错

- **扩展徽标变成 `!`**：本地服务没开。浏览器会照常自己下，没有损失。双击 `start-server.cmd` 即可。
- **端口被占用**：`start-server.cmd` 里的 `--port 6800` 改成别的（如 6801），同时在扩展设置页把端口改成一致。
- **Windows Defender 提示未知发布者**：exe 没代码签名，选"仍要运行"；不放心就用 `dl.py` 自己跑。
- **开机自启**（可选，管理员身份运行一次）：
  ```
  schtasks /create /tn "本地下载加速" /tr "\"<本文件夹完整路径>\dl.exe\" --serve --port 6800" /sc onlogon /rl highest
  ```
